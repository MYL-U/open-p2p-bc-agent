## 课题与使用场景

**所选课题**：基于 Open P2P（Pixels2Play）的游戏行为克隆智能体，输入游戏画面帧、输出预测的键盘与鼠标操作。选用理由：该课题任务边界清晰、以离线推理为主，适合单人独立完成且评测指标可量化复查。

**主要使用场景**：在课内环境中，通过离线帧推理得到模型的键鼠预测，并以可复查的量化指标评估其行为克隆质量。

**课内交付边界**：推理与评测均在老师提供的 GPU 服务器上完成；课内不做真机实时操控的现场演示，改用录屏方式呈现主路径，配合逐帧比对作为验收载体。实机游玩仅作为可选拓展，不进入主线验收。

## 必做与不做

### 必做（9 天结束时要能演示、能验收）

1. 跑通官方 150M 预训练权重的完整离线推理流程，整理可复现命令。
2. 仅使用官方 `--toy` 参数获取 toy 子集数据；后续如需更多数据，使用官方分批参数，绝不下载完整数据集。
3. 从 toy 子集中划分约 200 帧的隔离测试集，校验测试帧与训练帧不重叠、无数据泄露（口径：测试帧不得出现在任何微调/训练数据中；本课题主线不微调，此约束作为数据隔离硬性校验保留）。
4. 书面定义评测指标（按键一致率、鼠标皮尔逊相关系数），定义完备、他人可复现。（书面定义见附录 A）
5. 完成"模型输出 vs 人类标注"逐帧对照，生成录屏或截图可视化材料。
6. 记录基线指标，允许与参考水平（按键一致率≈55%、鼠标相关系数≈0.5）存在偏差，如实记录。

### 不做（明确排除）

1. 不下载完整 p2p-full-data 全集数据集。
2. 课内不做真机实时在线操控的现场演示，不额外搭建本地 Windows 环境、不依赖本地 Recap 工具。
3. 主线只用官方 150M 原始预训练权重，不做多模型对比、多游戏混合训练。

### 可选扩展（单列，留待主线通过后择一开展；顺序按指导书 4.6 排列）

- 扩展 A（微调）：单款游戏约 2 小时量级可训练数据，对照目标为微调后按键一致率约 +8 个百分点或鼠标相关系数约 +0.08；需额外算力与微调数据。
- 扩展 B（文本指令）：自然语言指令在启动时启用（`--input_text`），运行中不可切换；准备 2 个有成败标准的短任务场景，每场景带指令/不带指令各试跑约 10 次，报告任务完成率。
- 扩展 C（推理性能）：固定硬件上对约 200 帧批量推理计时并做至少一种优化，报告优化前后耗时/帧率，并说明是否影响按键一致率。
- 扩展 D（自采数据）：自录约 30 分钟量级画面与键鼠日志，转仓库格式后自建测试集评测。

首选意向：**扩展 A（微调）**，以主线全部自测通过为前提再启动；数据与算力优先复用现有 GPU 服务器资源。

## 主路径与验收

**主路径**（从启动到获得主结果的关键步骤）：

1. 登录老师提供的 GPU 服务器，按官方 `uv` 流程初始化环境（自动创建虚拟环境并安装依赖，替代原手动 venv 方案，见附录 C）。
2. 使用 `--toy` 参数下载 toy 子集数据，下载官方 150M 权重。
3. 运行离线推理脚本，加载权重对 toy 子集逐帧生成键鼠预测。
4. 从 toy 子集中划分约 200 帧隔离测试集。
5. 计算按键一致率与鼠标相关系数，得到基线指标。
6. 完成"模型输出 vs 人类标注"逐帧对照并录屏。
7. 整理复现命令与指标表，撰写结课报告。

**验收说明**（前提 → 操作 → 结果）：

1. 在服务器已完成环境与依赖安装的前提下 → 运行下载脚本获取 toy 子集与 150M 权重 → 应能看到权重文件完整性校验通过，脚本正常加载权重。
2. 在已划分隔离测试集的前提下 → 运行指标计算代码 → 应输出按键一致率（预期约 55%）与鼠标相关系数（预期约 0.5），且测试帧与训练帧无重叠。
3. 在已跑通推理的前提下 → 对同一测试片段执行逐帧对照并录屏 → 应能展示模型预测与人类标注的按键、鼠标差异，形成可视化材料。

## 风险与依赖

- **环境风险**：Python/依赖版本不匹配导致权重加载或推理脚本报错。应对：先在服务器建立独立虚拟环境，按仓库要求安装依赖，排错聚焦于环境层面。（注：官方仓库用 `uv` 统一管理依赖，按锁文件自动解析 Python 版本，详见附录 C。）
- **算力风险**：服务器算力或显存有限，大批量推理耗时。应对：以约 200 帧的小规模测试集为主，控制推理规模，必要时缩小范围。
- **数据风险**：误拉取全量数据集，或测试/训练帧重叠导致数据泄露。应对：严格只用 `--toy` 与官方分批参数，划分后做重叠校验。
- **真机/外设风险**：课内无真机与 Recap 环境。应对：改用录屏+逐帧比对呈现主路径，避免依赖实机。
- **指标风险**：指标定义模糊导致他人无法复现。应对：在报告中给出完备书面定义与计算逻辑（见附录 A）。

## 附录 A（草稿，待确认）：评测指标书面定义

> 以下定义由 AI 协助起草，用于满足"必做 4"的书面化要求，待第 5 天按仓库实际输出格式核对后定稿。

### A.1 按键一致率（Key Agreement Rate）

- **输入**：测试集共 N 帧，每帧有模型预测按键动作 `pred_t` 与人类标注按键动作 `label_t`（t = 1..N）。
- **单帧判定**：将动作展开为按键集合（含"无按键"），`match_t = 1` 当且仅当模型预测按键集合与人类标注按键集合**完全相同**，否则为 0。
- **指标值**：`KeyAgree = (1/N) * Σ_t match_t`，取值 [0, 1]，报告为百分数。
- **口径说明**：① 键位编码与动作头格式以仓库 `action head` 定义为准；② 若官方动作头为多键组合，按集合完全相等判定；③ 若出现官方未覆盖的键，需在报告中注明并决定是否剔除该帧。
- **参考水平**：≈55%。

### A.2 鼠标皮尔逊相关系数（Mouse Pearson Correlation）

- **输入**：测试集 N 帧，每帧模型预测鼠标增量 `(dx̂_t, dŷ_t)` 与人类标注增量 `(dx_t, dy_t)`。
- **单轴相关系数**：对 x、y 两轴分别计算

  `r = [Σ(x_t - x̄)(ŷ_t - ȳ)] / sqrt(Σ(x_t - x̄)² · Σ(ŷ_t - ȳ)²)`

- **指标值**：报告 `r_x` 与 `r_y`，并给出综合值（默认取两轴均值）。
- **口径说明**：① 必须逐帧对齐后计算，错位即视为口径错误；② 对整帧无鼠标位移（标注方差为 0）的情况，定义该轴相关系数为 0 或跳过该帧，报告中须写明采用哪种并保持统一；③ 鼠标坐标系以仓库标注格式为准（像素增量 / 归一化增量）。
- **参考水平**：≈0.5。

### A.3 可复现性要求

- 评测脚本输入：测试集文件路径 + 模型预测文件路径；输出：两个指标值 + 逐帧明细表（帧号、预测、标注、是否一致）。
- 脚本参数、随机种子、数据划分规则全部固定并写入报告，保证他人可复现。

### A.4 关于"任务完成率"口径（指导书 4.6 评测口径之一）

- 指导书定义的"任务完成率"＝固定开局下、达到事先写明成功条件的试跑比例，适用于实机/带指令试跑场景。
- 本课题主线为**离线帧推理**，课内无实机固定开局试跑条件，故主线**不采用任务完成率**作为指标；该口径仅在可选扩展 B（文本指令对照）中实施，届时按指导书定义执行。

### A.5 帧定义（指导书 4.6 评测口径）

- 帧：一帧画面及其人类键鼠标注；测试集按帧组织，逐帧对齐后计算上述指标。

## 附录 C（AI 补充，已按官方仓库核实）：官方仓库环境要点

- 仓库地址：`https://github.com/elefant-ai/open-p2p`（MIT 协议）。
- **依赖管理不使用 pip 手动安装**，由 `uv` 按 `pyproject.toml` / `uv.lock` 统一管理，`uv` 会自动解析 Python 版本并创建虚拟环境；因此原计划"手动建 Python 3.10 venv"调整为**以官方 `uv` 流程为准**，避免版本不匹配。
- 下载 toy 子集：`uv run python scripts/download_data.py --toy`
- 下载 150M 权重：`uv run python scripts/download_checkpoints.py 150M`（权重落在 `checkpoints/150M/`）
- 离线推理：`uv run elefant/policy_model/inference.py --config checkpoints/150M/model_config.yaml --checkpoint_path checkpoints/150M/checkpoint-step=00500000.ckpt`
- 需先 `uv run huggingface-cli login`（Gemma tokenizer 需要 HF 登录）。
- 文本指令模式须在启动时加 `--input_text`，运行中不可切换。
- 具体环境初始化命令见 `scripts/day2_setup.sh`。
