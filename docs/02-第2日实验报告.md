| # | 名称 | 职责 | 输入 → 输出（上下游关系） |
|---|------|------|--------------------------|
| 1 | 数据层 | toy 子集获取与组织；测试集划分与隔离校验 | HF 官方 toy 数据 → `dataset/`（VideoAnnotation protobuf，逐帧含 `user_action`：键盘 keys、鼠标 delta/scroll/buttons、`is_known`）→ 供推理层与评测层 |
| 2 | 环境层 | 服务器初始化、依赖安装（uv 统一管理） | 官方仓库代码 → 可运行推理的虚拟环境 → 支撑权重、推理、评测、演示各层 |
| 3 | 权重层 | 150M 权重获取与完整性自检 | 官方 150M 权重 → `checkpoints/150M/`（model_config.yaml + ckpt）→ 供推理层加载 |
| 4 | 推理层 | 加载权重逐帧生成键鼠预测 | 帧（192×192）+ 权重 → Action（keys、mouse_buttons、mouse_delta_px）；官方 Unix Domain Socket（UDS）推理服务 + 自研采集客户端（第 3 天产出） |
| 5 | 评测层 | 按键一致率、鼠标皮尔逊相关系数、逐帧明细 | 预测 JSONL + 人类标注 → 两项指标 + 逐帧对照表 → 供演示层 |

## 技术选型

| 决策点 | 方案 A | 方案 B | 结论与理由 |
|--------|--------|--------|-----------|
| 环境管理 | 官方 uv（锁文件统一管理） | 手动 venv + pip 安装 | 选 A：官方依赖由 `uv.lock` 管理，pip 易版本漂移；实测 uv 自动解析 Python 3.13.2 并完成 642 个依赖安装 |
| 推理预测采集 | 自研 UDS 客户端（逐帧发 Frame 收 Action） | 仅依赖服务端旁路 `--model_records_path` | 选 A：`inference.py` 无 `--output` 参数，预测只能经 UDS 返回；旁路记录含 KV cache，仅作调试交叉验证 |
| 鼠标评测对象 | 解码后像素位移（truncated_normal 采样） | 离散 bin 索引 | 选 A：动作空间将鼠标 x/y 离散为 23/16 个 bin，默认采样解码（X_STD=96、Y_STD=22）；解码后位移与人类标注同量纲才可比，与参考值 ≈0.5 吻合 |
| 模型/数据获取通道 | 服务器直连官方 HF | 本机镜像下载后上传 | 选 B（今日实际调整）：服务器出口对 HF 生态全站不可达且 DNS 被污染；本机可直连镜像（约 5.7MB/s），本机下载 → SFTP 上传服务器 |

## 对第 1 日报告的修订说明

与已提交的第 1 日报告相比有两处不同，原因说明如下：

1. **环境初始化方式**：第 1 日主路径写"创建 Python 3.10 虚拟环境"，现改为**官方 uv 流程**（按锁文件自动建 venv 并解析版本，实测 3.13.2）。原因：官方依赖由 uv 统一管理，手动 pip 无法对齐锁文件、易版本漂移；uv 流程与官方一致、可复现性更好。
2. **可选扩展顺序**：第 1 日报告按 A/C/D/B 列举，现按指导书 4.6 官方顺序调整为 **A（微调）/B（文本指令）/C（推理性能）/D（自采数据）**，主线自测通过后首选 A。

## 问题、计划与 AI 沟通

### 不成功的沟通

1. 早期让助手直接给出"完整可运行架构"，得到脱离官方源码的方案（如假设存在 `--output` 参数）。调整：收窄为逐文件核实官方脚本后再下结论，一次并行核实 5 个关键文件。
2. 远程命令经 PowerShell 传参多次因引号转义失败。调整：命令写入本地文件、SSH 工具从文件读取执行，一次解决。
3. 服务器 git clone 长时间卡死（传输层无进展）。调整：加 HTTP/1.1 + shallow clone；uv 的 git 依赖改用系统 git 后端并配镜像。
4. 服务器访问 HF 镜像遇 DNS 污染（解析到不可达 IP）。调整：改本机镜像下载后上传。

### 比较有效的沟通

1. 把"文件范围 + 验收方式"写进提问（如核实 `--toy` 是否指向 toy 仓库、去掉后才触发全量），得到可直接写入报告的确证事实。
2. 并行核实 5 个关键文件，确认"UDS 推理服务"与"鼠标离散化"两个决定后续实现的事实。
3. 密钥经环境变量注入、命令走本地文件，避免明文落盘。
